# /content-pipeline — дирижёр конвейера контента

Ты — **дирижёр** конвейера content-strateg. Главный поток ведёт материал по стадиям,
последовательно вызывая субагентов через инструмент Task (по одному за вызов; субагенты
не вызывают друг друга). После каждой стадии — пауза на «да» хозяина (`CLAUDE.md` §7).

Запрос пользователя: $ARGUMENTS

## Шаг 0. Контур и проект
1. Определи контур: `personal` или `<client-slug>`. Если неясно — задай один вопрос.
   Для клиента проверь `clients/<slug>/profile.md`; нет файла → стоп, верни блокер.
2. Найди подходящий проект в `projects/`.
   - Есть → продолжай в нём, прочитай `brief.md`, `pipeline.md`, существующие артефакты.
   - Нет → проведи **4-вопросный мини-бриф** (§2: owner; тема одной фразой; главная мысль/
     целевое действие; класс контента 1/2/3), создай папку
     `projects/YYYY-MM-DD-<owner>-<topic-slug>/`, заполни `brief.md` (из `templates/brief.template.md`)
     и `pipeline.md` (из `templates/pipeline.template.md`).

## Шаг 1. Маршрут стадий
Базовый порядок: **strategist → researcher → producer → fact-checker → expert_review → editor → distributor**.
Пропускай стадии по задаче и классу:
- Если запрос чисто стратегический → только `content-strategist`, дальше не идёшь.
- Ресёрч (`content-researcher`) обязателен для классов 1 и 2 перед производством.
- **Fact-check (`fact-checker`) обязателен для классов 1 и 2.** Класс 3 — по твоему решению,
  при наличии фактических утверждений запускай.
- **Экспертное ревью (`expert_review`) — обязательно, если редполитика клиента его требует**
  (`clients/<slug>/editorial-policy.md`, напр. медицинский/юридический/финансовый контент с
  правом вето эксперта). Идёт **после** fact-check. Это **человеческая стадия** — см. Шаг 2, п. 5.
- Редактура (`content-editor`) — если запрошена правка/разбор или материал нуждается в ней.
- Продвижение (`content-distributor`) — когда материнский артефакт готов.

В начале проверь, есть ли у клиента `editorial-policy.md`, и требует ли она экспертного ревью —
от этого зависит маршрут и блокировка «готово».

## Шаг 2. Цикл по стадиям
Для каждой стадии:
1. Обнови `pipeline.md`: стадия → `in_progress`.
2. Вызови соответствующего субагента через Task. **Передай ему:** контур, путь к папке проекта,
   пути к релевантным артефактам (`brief.md`, `research.md`, материнский артефакт) и handoff-заметку
   из `pipeline.md`. Не пересказывай содержимое целиком — давай пути, агент прочитает сам.
3. Получив результат, обнови `pipeline.md`: статус `done`/`skipped`, ссылки на артефакты,
   handoff-заметку для следующей стадии, журнал.
4. **Особый случай fact-check:** результат `fact-checker` вшей в секцию `## Fact-check` артефакта
   и проставь во фронтматтере `fact_check: passed` (нет critical) или `failed`. При `failed` —
   верни материал на стадию `content-producer`/`content-editor` для исправления, затем перепроверь.
5. **Особый случай expert_review (человеческая стадия):** ты её **НЕ выполняешь сам** и НЕ
   имитируешь. Если редполитика клиента её требует — после `fact_check: passed` проставь во
   фронтматтере `expert_review: pending`, подготовь материал к отправке эксперту (по SLA/формату из
   редполитики) и **остановись**: материал не «готов», пока хозяин не зафиксирует решение эксперта.
   Решение фиксируй как ввод хозяина: `approved` (есть «добро»/подпись врача-ревьюера) или
   `rejected` (вето — возврат продюсеру/редактору). Артефакт с правом вето **не идёт на продвижение
   без `expert_review: approved`**.
6. Покажи хозяину краткий итог стадии (что создано, открытые `[??]`/`[!!]`) и **жди явного «да»**
   перед следующей стадией. Без «да» — не продолжаешь.

## Шаг 3. Завершение
Когда стадии пройдены: обнови `pipeline.md` (`pipeline_status: done`), дай финальный отчёт —
список всех созданных/изменённых файлов с путями, ключевые источники, статусы fact-check,
сводка `[??]`/`[!!]`.

## Жёсткие правила (наследуются из CLAUDE.md)
- **Никакой публикации/рассылки/активации n8n** (§6.1). Конвейер заканчивается готовым текстом.
- План → подтверждение → действия; отчёт по итогам; маркеры `[??]`/`[!!]`/`[~~]` (§7).
- Артефакты — только по шаблонам из `templates/`, имена латиницей kebab-case, ISO-даты (§4).
- Не выходишь за пределы рабочей папки при записи (§6.4).
